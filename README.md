## １．アプリの概要

アプリ名:あとがたり -場所と思い出をつなぐお出かけログ-
キャッチコピー:思い出が次のお出かけになる

場所をきっかけに、あの日の体験を思い出し、未来のお出かけにつなげる「おでかけログ」です。
過去の体験を記録することで思い出への手がかりとなり、「また行こう」のサイクルを作ります。

## ２．アイデアが生まれたきっかけ

### 2-1. きっかけとなった体験・感情

子供の頃、夏休みに祖父母の家に行く時に栞を作っていました。
やりたいこと、持ち物等を細かに計画して、旅行前も、旅行中も、旅行後も見返して楽しんでいた記憶があります。
大人になり、友達と遊ぶ機会が増えてくると、過去のお出かけを振り返る際に記憶が薄れていると感じることが多々あります。
社会人になってから友人と会う頻度が減ったので、人によっては年に１度会うかどうかという程度になりました。
前回どこに行って、どんなことを感じて、どんな気候で、どういう流れで…といったことを話すのですが、
段々と記憶が薄れてしまい、上手く話すことができないと感じることが多くなってしまいました。
感じたことが確かにあったはずなのにぱっと思い出せないことを寂しく感じるようになりました。

そこで記録に残すことで共有したり、次のお出かけの参考にしたり、コミュニケーションにつなげることができると考えました。
子供の頃の栞のように行きたい場所を記録して、行った場所を記録する。
「ここ行きたい」から「また行こう」までを共有できるものを作りたいと考え、本アプリを作成することにしました。

### 2-2. なぜそれが「気になった」のか

#### 自分の性格：人と関わるのが好きだが、経験を言語化のは苦手

#### 過去の経験：

- 人と関わるのが好きで、友達とよく遊ぶ
- 「あの時どうだった？」と聞かれてもうまく答えられない
- ぼんやりとした感情しか覚えておらず、面白かったや楽しかったといった表面的なことしか話せない

#### 大切にしている価値観：

思い出を共有することで人との繋がりを深めること

## 3. 課題の整理

### 3-1. 表に見えている困りごと

お出かけの内容を思い出せない・忘れてしまう

- どうだった？と聞かれた時の言語化が難しい
- 何を着ていたか
- 何をしたか
- お店の名前
- その時の天気
- その場所で感じたこと

### 3-2. 本当に解決したい課題は何か

思い出せないことで体験を人に伝えられない。
共有できないことで、次のお出かけにも生かすことができていない。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

ターゲット：20代～30代、友人とのお出かけを大切にしている人

環境・状況

- 休日に友人と遊びに出かけることが多い
- １人の友人に対して会う頻度が少なくなっている（3か月に１度、半年に１度、１年に１度等）
- 会った時に「前回どこ行ったっけ？」「あの時どうだった？」と過去が話題になることが多い

現在の課題

- 思い出せない
    
    会話の中でどうだったと聞かれた時にぼんやりとした記憶しか思い出せない
    
- 情報が分散してしまう
    
    記録が写真やその時に保存したInstagram、GoogleMap、ウェブサイト等分散してしまい、何度も調べ直している
    
- 記録が続かない
    
    手間のかかる日記アプリは続かないが、思い出は残したい
    

### このアプリを使うことでどう解決できるか

- 場所に情報を紐づけて記録
    
    場所に日付やメモ等の情報を紐づけることで、その日のルートや詳細な情報を振り返ることができる
    
- 情報を一つのアプリに集約
    
    写真やInstagram等複数の媒体を横断して探す手間がなくなる
    
- 場所と日付だけでOK
    
    手軽に行った場所を記録することができる
    

### 4-2. 自分とユーザーの距離

本アプリのターゲットユーザー：現在の自分自身

なぜその距離感なのか：
自分自身が社会人になってから、友人と会う頻度が減り、近況報告や前回の振り返りとして少し前にあった出来事を話すことが増えた。
その際に「あの時どうだったか」を思い出せないために、うまく共有できないことをもどかしく感じていた。

- 「前回どこに行ったっけ」「今度○○行くんだけど、前行った時どこ行った？」　→LINEや写真を遡るため時間がかかる
- 「あのカフェ美味しかったよね」　→店名を忘れて調べなおす

だからこそ、過去の体験を思い出すきっかけを作ることで「思い出せない」という課題を解決したいと考えた

### 4-3.実際に使われる可能性について

- 最初に使ってくれそうな人
    - お出かけした際に写真は撮るが、振り返ろうと思った際に写真が多すぎて振り返りにくいと感じている方
    - お出かけの記録を何らかの形で残したいが日記アプリは続かない方
    - 友達と話す際に「前回どこ行ったっけ？」と話題になり、思い出すのに時間がかかっていると感じている方
- アプリを使う場面
    - お出かけ計画時
    「前に〇〇に行った時、どこに行った？」「前行って楽しかったあの場所どこだっけ？」と過去のお出かけを確認したいタイミング
        
        →過去の楽しかった場所を思い出して、次の計画に活かせる
        
    - お出かけ中
        
        カフェや観光地に到着した時に今いる場所を登録するタイミング
        
        →手軽に記録できるため、お出かけを楽しみながら記録できる
        
    - 帰宅後
    今日のお出かけを振り返るタイミング
        
        →登録した場所に写真やメモを追加し、「今日どこ行ったか」がすぐにわかる
        
    - 数か月後
    「今度○○に行くのだけどおすすめある？」と友達に聞かれたタイミング
        
        →「あの時楽しかった場所」をすぐに思い出して共有できる
        
- 今の生活の中で代わりに使っているものは何か？
    
    | やりたいこと | 使っているもの | 課題 |
    | --- | --- | --- |
    | 行った場所の保存 | GoogleMap | 日付やメモが紐づかない |
    | 場所の情報収集 | Instagram・TilTok・食べログ | 情報が分散していて探しにくい |
    | 思い出の保存 | 写真アプリ・LINEのアルバム | 写真が多すぎて振り返りにくい |
    | 思い出の記録 | 日記・メモ・記憶の中 | 記録が続かない |
    | 旅行の計画 | 旅行アプリ（詳しくは既存サービスに記載） | 「行った」記録と「行きたい」が別々 |
- それを置き換えてまで使う理由
    現在は様々な媒体を使い分けながらお出かけの計画～記録を行っている。その結果、以下のような課題がある。
    
    - 情報が分散
        
        GoogleMapやInstagram、写真アプリ等記録がバラバラで探しにくい
        
    - 思い出すのに手間がかかる
        
        お出かけの体験を思い出す際に写真をさかのぼる、再検索して記憶をたどる必要がある
        
    - 記録が続かない
        
        日記アプリは面倒で続かない
        
    **本サービスでは、過去に訪れた場所に情報を紐づけることで過去の体験を思い出しやすくします。**
    
    - 情報を一つのアプリに集約
        
        場所、日付、写真、メモを一つのアプリで管理
        複数のアプリを横断して探す手間がなくせる
        
    - 他者と過去の体験を共有できる
        
        過去の楽しかった体験をすぐに検索できることで友達との会話で共有することができる
        
    - 次のお出かけに生かすことができるようになる
        
        前回のルートを参考にして次の計画を立てやすい
        前回楽しかった場所をもう一度訪れることができる
        
    
    このように過去の体験を未来へつなげることができる点に価値があると考える。
    

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

サービスとの出会い

- 写真だけで記録していたが、振り返りにくいと感じている時
- GoogleMapやInstagram等複数の媒体で記録しているが、行った場所の情報を一つのアプリで管理したいと思ったとき
- お出かけを記録したいけど、日記アプリでは続かないと感じているとき

登録・導入でユーザーがすること

- STEP1：アプリを開く
    
    トップ画面で「このアプリでできること」を確認
    「場所を軸に記録できる」「手軽に記録できる」「次のお出かけに活かせる」アプリであることを理解
    
- STEP2：ユーザー登録
    
    メールアドレスとパスワードで簡単に登録
    
- STEP３：最初の記録を作製
    
    「今日行った場所」を記録してみる
    場所と日付だけでOK
    

利用を続ける理由（必要性・価値）

- 「あの時、何をしたっけ」をすぐに思い出して共有できる
    
    →場所や日付等から検索できるため、複数のアプリを横断せずに思い出すことができる
    
- 記録だけではなく、次のお出かけに生かすことができる
    
    →場所と日付を記録するため、一日に何をしたのかを振り返ることができ、次のお出かけ時のルートの参考になる
    
- 手軽に続けられる
    
    まずは日付と場所のみの登録でOK、+αの情報は時間のある時に登録する形なので、手軽に記録できるため、続けやすい

- 旅行がメインのため、ちょっとしたお出かけを記録するにはハードルが高い

## 8. このアプリの懸念点とその対策

### 懸念点①

- 何が問題になりそうか：継続性
- なぜそう思うか：ペルソナとして記録したいが、日記は続かないという人物を設定している。色々な情報を記載すると記録への負荷が高い。
- そのために考えている対策：
    - 最低限の情報だけで記録を作成できるようにする
        - 「行った」ボタン一つで記録完了
        - 場所名と日付だけで記録を作成（写真、メモは後で追加）
    - 記録のハードルを下げる
        - 写真を撮るだけで位置情報と日付を自動取得（本リリース以降で実装）
        - GPSで現在地を取得し、その場で「行った」ボタンで登録できる

### 懸念点②

- 何が問題になりそうか：アプリを開く動機が薄い
- なぜそう思うか：過去の記録は記録する時点のユーザーにとって必須ではないから
- そのために考えている対策：
    - スタンプ・バッジ機能を追加することで記録したくなるような動機付けを作る
        - 「10か所訪問」「3日連続記録」「初めての場所」「名所訪問」等の達成でバッジを獲得
        - 訪問回数に応じてピンの色が変わる

### 懸念点③

- 何が問題になりそうか：情報の集約という価値を重視しすぎてしまうとMVPが複雑になってしまう
- なぜそう思うか：行きたい場所の登録からはじめてしまうとMVPとして必要な機能が増えすぎてしまう
    - そのために考えている対策：「過去の体験」を未来につなげることにフォーカスし、「行った場所」を登録、検索できることをMVPとする

※spotsテーブルの要否について
Google Maps APIのAutomatic APIの利用を検討しているため、場所名登録時にspotsテーブルを参照する必要性が薄いと考える。
MVP段階ではrecordsテーブルのみとし、本リリース時に分割することも視野に入れる

※google_place_idのカラムの要否について
placeIDは閉店や移転等でplace IDの情報が都度更新される可能性がある。このアプリは「あの日、あの場所で何を感じたか」を未来につなげるサービスであるため、その時時点の情報である方が良いと考える。
そのため、マーカー表示時の情報はplace IDではなく、緯度経度を用いる。
